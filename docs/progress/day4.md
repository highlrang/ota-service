# Day4
## 구현
### 작업내용
#### Customer API
- 고객 로그인 API
- 숙소 검색 API
  - 통합 Accommodation 기준 페이징 조회
  - 지역, 숙소타입, 침구타입, 숙박일, 인원, 요금, 매진 제외 조건 반영
- 객실 예약 API
  - 고객 이름, 연락처, 숙소/객실 코드, 숙박일, 결제수단/금액, 인원 정보 수신
  - 날짜별 RoomRate / RoomInventory 기준으로 예약 가능 여부 검증
  - 예약 생성, 결제 생성, 재고 차감 처리
- 숙소 상세 조회 API
  - 고객이 선택한 숙소의 상세 정보 조회
  - 예약 단위 객실 목록, 객실 이미지, 기간별 총액/재고/매진 여부 반환
- 비회원 예약 지원
  - 고객 예약 API는 로그인 사용자와 비회원 모두 호출 가능
  - 회원 예약이면 JWT의 accountId를 reservation.user_id에 저장
  - 비회원 예약이면 reservation.user_id는 NULL로 저장

### 의사결정
- 예약 시 객실 재고 및 요금 관련 로직의 일관성을 높인다.
  - 기존에는 숙소 등록 시 재고와 요금을 기간 단위로 받고 기본 재고, 기본 요금을 받고 있어서 그에 따라 예약 시 재고 차감 및 요금 적용 로직이 분기되어야 했다. 
  - 해당 부분 로직의 일관성을 높여 기능의 복잡도를 낮추기 위해 재고/요금 관리 단위를 기간별 입력, 일자별 저장 구조로 정리한다.
  - 최종적으로 예약/검색/판매 가능 여부 판정은 일자별 RoomInventory / RoomRate 만 참조한다.
  - 필요 시 추후 기간 단위 설정값 자체를 관리하는 별도 기간 그룹 재고/요금 스키마를 추가하여 기능을 확장한다.

- 숙소 검색은 통합 Accommodation 기준으로 조회한다.
  - 통합 숙소를 기준으로 검색 결과를 노출하고, 객실/요금/재고는 내부적으로 필터링에 활용한다.
  - 검색 API는 하나로 유지하되, 1차 검색 조건과 상세 필터를 optional 파라미터로 조합할 수 있게 설계한다.

- 결제 금액 검증을 서버에서 수행한다.
  - 고객이 전달한 결제 금액이 숙박 기간의 일자별 RoomRate 판매가 합계와 일치하는지 검증하여 잘못된 예약 요청을 방지한다.

- 고객 API의 인증 강도를 기능별로 분리한다.
  - 숙소 검색/상세 조회는 공개 API로 열어 비로그인 사용자도 조회 가능하게 한다.
  - 예약 생성은 선택 인증 API로 처리하여 로그인 고객은 accountId를 연결하고, 비회원은 익명 예약으로 처리한다.
  - 그 외 `/api/customer/**` API는 기존처럼 CUSTOMER 토큰을 요구한다.
