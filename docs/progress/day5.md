# Day5
## 구현
### 작업내용
- 상품 조회 성능 개선
  - 조회가 빈번한 홈 인기 숙소 목록 API 캐시 처리하여 데이터 조회 성능을 개선한다
- 상품 예약 데이터 정합성 개선
  - 고객 숙소 예약 시 순차적으로 처리하여 사용자가 경험하는 데이터 일관성을 확보한다 

### 의사결정
- 인기 숙소는 예약 생성 이벤트마다 캐시를 무효화하지 않고 TTL 기반으로 운영한다.
  - 인기 숙소 기준을 예약 수로 잡으면 예약 생성이 자주 발생하는 시간대에 전체 캐시 무효화가 반복되어 캐시 효율이 크게 떨어질 수 있다.
  - 따라서 인기 숙소 API는 실시간 강한 정합성보다 조회 성능을 우선하여 TTL 만료 시점에만 재계산되도록 구성한다.
  - 현재는 Spring Cache + Server Local Memory로 5분 TTL을 적용한다.
- 예약 생성 시 동시성 제어는 낙관적 락보다 비관적 락을 우선 적용한다.
  - 동일 숙소에 대한 예약 요청이 짧은 시간에 집중되면 선조회 후검증 방식만으로는 중복 예약을 막기 어렵다.
  - 예약은 충돌 발생 후 재시도 비용보다 잘못된 예약 확정 자체의 비용이 더 크므로 충돌을 사후 복구하는 방식보다 트랜잭션 시점에 선제적으로 방어하는 편이 안전하다.
  - 따라서 예약 가능 여부를 확인하는 시점에 대상 숙소 행을 비관적 락으로 점유해 하나의 요청만 검증과 생성 절차를 통과하도록 구성한다.
